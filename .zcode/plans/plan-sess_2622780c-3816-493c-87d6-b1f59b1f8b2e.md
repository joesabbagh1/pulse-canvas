# Synth Machine for Pulse Canvas

## Context

tek (Pulse Canvas) has 162 static catalog instruments, but no user-editable synthesizer: every patch is baked into `src/engine/instruments.ts`, and nothing synth-shaped persists in the piece JSON. The user wants a **synth machine** — a user-editable synth (wave, filter cutoff+resonance, ADSR, plus **glide/mono mode**) that works three ways:

1. **Canvas instrument** — blocks can use it, patterns play it, it routes through region buses like any instrument; patch edited in the sidebar Inspector.
2. **Dedicated Synth page** — new top-level tab with a bigger patch editor + playable keyboard for jamming/recording takes (reuses the Instruments-page machinery).
3. **Deck MCP** — agent can create/edit machines and play them.

Machines live **in the piece** (`piece.machines`), so they ride autosave, undo, share links, and .json files automatically. Factory presets in code are starting points for new machines; saved pieces are self-contained.

## Design

### Data model — `src/engine/synth.ts` (new)
- `SynthPatch = { wave: 'sawtooth'|'square'|'triangle'|'sine'|'fatsawtooth'; cutoff: number; q: number; attack: number; decay: number; sustain: number; release: number; mode: 'poly'|'mono'; glide: number; gain: number }`
- `SynthMachine = { id: string; name: string; short: string; hint: string; patch: SynthPatch }` (ids created as `syn-…` via `newId('syn')`)
- `PRESETS`: ~5 factory patches (acid lead, saw pad, square bass, soft pluck, warm keys) + `DEFAULT_PATCH`
- `machineInstrument(m): Instrument` — assembles a catalog-shaped entry (`category: 'synths'`, `pitched: true`, `steps: true`, `voice: 'synth'`, spread patch)
- Pure helpers exported for tests (cutoff normalization→Hz, glide timing, clamp tables)

### Registry — `src/engine/instruments.ts`
- `Instrument` union gains a `voice: 'synth'` variant carrying the patch fields.
- Module-level machine map + `setMachines(entries)` / `machineById(id)`; `instrumentById(id)` falls back to it. This single change makes **all ~18 existing call sites work** (block labels, `isMelodic`/`hasPitch`, pattern aliases, takes/waves validation, deck scene/plan, Inspector, InstrumentsPage, settings colors).
- `scheduler.ts`: widen `BlockKind` to include machine ids; add `'synth'` to `HELD_VOICES` so pattern notes hold their length (same as `acid`/`sustain`).

### Voice — `src/engine/synthVoices.ts` (new)
`SynthMachineVoices` class (one per `CatalogVoices`, like `MachineKit`/`AcidVoice`):
- **Poly mode**: per-machine lazily-built `Tone.PolySynth(Tone.Synth)` (oscillator = wave, envelope = ADSR) → shared `Tone.Filter(lowpass, cutoff, q)` → level gain → output. `triggerAttackRelease` for pattern notes; `triggerAttack` + released gate for held notes.
- **Mono mode**: per-machine persistent voice modeled on `AcidVoice` (`machine.ts:245`) — running `Tone.Oscillator` → gate gain → resonant filter, hand-scheduled gate, patch-driven ADSR and glide seconds (patch.glide; 0 = no slide).
- Patch edits apply lazily on the next note (compare stored patch before calling `synth.set` / ramping filter). `silence()`/`dispose()` clean up everything.
- Tone nodes stay behind lazy construction so jsdom tests stay safe (same discipline as `machine.ts`; pure math tested in `synth.test.ts`).

Dispatch: `catalogVoices.ts` gains `synthVoices` + `case 'synth'` in `play`/`attack`/`silence`/`dispose`. No mixer changes — blocks ride `Voices` default branch → `catalog.play`, region buses/lanes/live path all work as-is.

### Piece schema — `src/piece.ts`, `src/readPiece.ts`
- `Piece.machines?: SynthMachine[]` (absent → `[]`, like waves/takes). `toPiece` includes machines when non-empty.
- `readPiece`: `LIMITS.machines = 24`; `readMachine` clamps every param (cutoff 60–14000 Hz, q 0.1–18, attack 0–4 s, decay 0.01–4 s, sustain 0–1, release 0.01–6 s, glide 0–0.5 s, gain −30–0 dB, name/short text limits). Machines are read **before** blocks/takes/waves, and a local `machineIds` set lets block `kind`s, take instruments, and wave instruments reference machines — unknown refs are still dropped, as today.

### App wiring — `src/App.tsx`
- `machines` state seeded from the loaded piece; an effect syncs the registry: `setMachines(machines.map(machineInstrument))`.
- Machines join: autosave deps + `toPiece` calls (autosave, `pieceJson`, `currentPiece`), `restore()` (undo), `replaceWith()` (share/file/example open).
- CRUD: `addMachine(preset?)`, `editMachine(id, patch)`, `removeMachine(id)` — removal retargets blocks using it to `'tone'` with a toast.
- Render `<SynthPage>` when `route === 'synth'` (canvas parks via existing `parked` logic); `document.title` case; Escape returns to canvas via existing shortcut.

### UI
- **`src/ui/route.ts`** — add `'synth'` to `Route` + `PAGES`. **`src/TopBar.tsx`** — `{ route: 'synth', label: 'Synth' }` in `APP_TABS`.
- **`src/SynthPage.tsx`** (new) — mirrors InstrumentsPage layout: left list of this piece's machines + "New from preset…" menu; right stage with patch editor (name/short fields, wave segmented buttons, poly/mono mode, cutoff + resonance + ADSR + glide(mono) + gain sliders, Delete with `confirmDialog`) and the playable keyboard via `InstrumentSurface` + `useRecorder` (exported from `InstrumentsPage.tsx` — minimal change there). `playingFor` (`src/engine/playing.ts`) falls back to a keyboard layout for machine ids. Takes save/place exactly like instrument takes.
- **`src/ui/Slider.tsx`** (new) — extract the `Slider` from `RegionInspector.tsx`; both panels use it.
- **`src/Inspector.tsx`** — instrument `Select` gains a "Synth machines" group plus a "New synth machine…" action entry; when a block's kind is a machine, show its patch fields inline (shared compact patch-fields component) and the hint.
- **`src/canvas/CanvasControls.tsx`** — AddDock lists machines under Synths so blocks can be added directly.

### Deck
- Snapshot gains `machines`; `src/deck/build.ts` new `BUILD_OPS` entry `synth` (`list` / `add name … [preset|params]` / `edit <ref> …` / `remove <ref>`), `resolveKind` also matches machine names/ids; `src/deck/effects.ts` adds `putMachine`/`dropMachine`; `mcp/server.ts` registers a `synth` tool; App's `useDeck` handlers apply the effects.

### Docs
- `src/GuidePage.tsx`: short section — what machines are, Synth page, Inspector editing, `synth` deck op.
